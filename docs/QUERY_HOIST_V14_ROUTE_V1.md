## Admission and Selection

The new optional dependency uses the existing V14 crate and its exact one-root
compiler expectation roster at the existing fe2o3 8efd4fd pin. The new artifact
opener retains canonical two-file content-addressed observation admission and
additionally requires Wave64, 17 explicit entries with 116-byte extent,
implicit offset 120/size 256, total kernarg 376/alignment 8, and zero emitted
SGPR/VGPR spills, AGPR, private memory and LDS. This does not turn the observed
handoff digest into a full typed proof or numerical theorem.

The existing finite fixture's `candidate` directory is not a canonical adapter
artifact path. A later installer must retain the already accepted HSACO and
observation bytes under `fe2o3-engineering-v1/<observation-content-id>` without
relaxing path admission. No installation is part of this source change.

The dedicated constructor checks both separately loaded v11 and v14 identities
before allocation and records the private bindings. V14 remains unselected.
The new terminal selector requires matching prior bindings and the existing
fresh target TP1/capacity32, ordered, pruned, MFMA-global/C1-layer, v8 FP32 head
and v11 argmax profile. All fallible checks precede route state publication.
Old selectors remain available as the V5 control and cannot be changed later.

`attention_mode()` reports the actual selected policy: `baseline`, `wave`, or
`query-hoist-v14`. In the fixed new C1/32-row profile, `wave` means resident V5;
legacy row profiles still choose their original wave/baseline image versions.
Only the GQA root changes. Arguments, allocation geometry, ordered group shape,
arithmetic, MFMA multirow projections, C1 single-row projections and the v8/v11
head remain unchanged. The loop scalar remains max(active positions) + 1.
