# M1 Tokenizer Execution

Ferric executes the tokenizer only through `AuthenticatedTokenizer`, whose
private seal is constructed after the complete pinned `tokenizer.json` stream
has passed its byte identity and closed-schema checks. The authority retains
the exact 151,643-entry base vocabulary and all 151,387 ordered merge pairs;
there is no descriptor-only tokenizer constructor.

The implemented encode path is closed to the one authenticated Qwen3 program:

- input is valid Rust UTF-8 and is NFC-normalized by
  `unicode-normalization-alignments` 0.1.12, whose generated normalization
  tables are Unicode 9.0.0;
- the one schema-authenticated Qwen3 Split expression is compiled once into
  a private `onig` 6.5.3 regex backed by `onig_sys` 69.9.3 and bundled
  Oniguruma Unicode 16.0.0 tables;
- callers cannot supply a regex, tokenizer file, vocabulary, merge list,
  training input, or network/hub source;
- every split is mapped through the pinned GPT-2 ByteLevel alphabet;
- BPE repeatedly applies the lowest-ranked adjacent merge, with no dropout,
  unknown token, prefix, suffix, byte fallback, or merge bypass; and
- the 26 exact added tokens use leftmost-longest matching, then their admitted
  ID order as the final tie break.

The first 14 added tokens have their authenticated `special` bit set. Encoding
rejects these strings by default and requires `SpecialTokenEncodePolicy::Allow`
to emit their exact IDs. The remaining 12 added tokens are recognized under
either policy. Decode either preserves all added-token content or omits only
the 14 special tokens. Decode returns bytes because an arbitrary base-token
slice is not necessarily valid UTF-8.

Each call validates caller bounds against fixed hard ceilings: 32 KiB input,
128 KiB normalized text, 8,192 token IDs, 128 KiB decoded output, and
16,777,216 charged operations. All counters and output growth are checked.
Exhausting any limit fails instead of truncating or selecting a fallback
tokenizer.

The deterministic 640-case corpus in
`qwen3-tokenizer-differential.txt` was generated by an independently invoked
exact `tokenizers` 0.22.2 wheel from the authenticated tokenizer bytes. It
covers multilingual and normalization pairs, Unicode category changes,
whitespace and line endings, case-insensitive contractions, negative
lookahead boundaries, random hostile compositions, and every special-token
policy input. This is differential test evidence, not a Verus equivalence
theorem or a claim about arbitrary tokenizer configurations. Ferric does not
apply the chat template, add implicit special tokens, expose offsets, stream
text, or provide the general Hugging Face tokenizer API.

The complete registry closure is pinned in `Cargo.lock` and canonically
admitted by `proofs/RUNTIME_DEPENDENCY_TCB`. Oniguruma's bundled C build,
unsafe Rust/C FFI, regex implementation, Unicode 16 tables, and the alignment
crate's Unicode 9 normalization implementation and tables are `Contracted`.
No source proof promotes those components to `Proved`.
