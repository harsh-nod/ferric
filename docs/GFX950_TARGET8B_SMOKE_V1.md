# Asrock GFX950 Qwen3-8B Smoke

One actual **Qwen3-8B, batch-one, single-GPU BF16** engineering run on AMD Instinct
MI350X (`gfx950`) produced two greedy tokens matching the frozen independent
reference. This is a **two-token smoke**, not a performance qualification,
700 tokens/s achievement, serving result or single-launch megakernel.
It is separate from the [Draft06B observations](GFX950_DECODE_OBSERVATIONS_V1.md)
and is not included in their configuration comparison.

The unchanged TP v1 controller uses token-at-a-time prefill: five prompt forwards
produce the first choice, then one additional forward produces the second.
Rank zero executes 544 dispatches per forward. This is a full-model,
multi-dispatch engineering path, with the existing host-staged FP32 rank-order
reduction and BF16 residual contract, not the Draft06B profile or a new fused
decode implementation.

The frozen comparator independently revalidated exact token and byte parity,
dispatch counts, KV cursor, controller/live-worker hashes, artifact identity and
successful worker closure. A separate exact-plan check required TP1, capacity 16
and the selected device. Input/source/provenance checksum rechecks passed.
Saved pre/post observations showed zero graphics and memory-controller activity,
unchanged 283 MB resident VRAM, stable topology generation and only the checked
zero-allocation monitor. These are bounded recorded checks, not system-wide
exclusivity or hardware attestation. No Draft paged-pool retirement or
allocation-guard claim is inherited by this different execution path.

## Independent Reference

The reference was generated **earlier on AMD Instinct MI300X**, not newly on
Asrock. Its pinned execution used offline `transformers.generate`, BF16 SDPA,
PyTorch `2.12.1+rocm7.2` and Transformers `4.51.0`. Two 32-token greedy passes
agreed. This candidate checked **only their first two output tokens and bytes**;
it does not establish full 32-token parity or general numerical correctness.
The reference and candidate use the same pinned model revision and canonical
deployment-bundle identity. This is an independent numerical oracle, not proof
that every floating-point operation is identical across implementations.
