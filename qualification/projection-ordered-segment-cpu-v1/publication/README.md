# Ordered Segment Local Integration and Publication V2

Source-only helper; root owns execution and integration. Run only after the
bounded CPU qualifier succeeds and its metadata/source courier is retained
under a fresh W original-path tree. No future completion SHA or success count
is embedded. No tested module is imported and no tests, compiler or GPU run.
The v2 controller and corrected Ferric-v2 proposal are required, with the original
runtime-v1 proposal. The failed v1 target must remain unchanged. New output labels
start at v2; record schema strings and first-success publication destination stay
unchanged. The actual primary seventeen-test observation is bound at SHA
`7371c32e...`; this remains a primary-agent observation, not a remote ownership
receipt. The CLI remains unchanged.

```text
python3 -B publish.py W/RETAINED_ROOT/projection-ordered-segment-cpu-v228-vN/complete.json ACTUAL_SHA256
```

The helper verifies all actual raw bodies, natural successful phase/stream
joins, named test results, five Cargo executable identities and sixty formatted
source bodies. Counts derive from the actual runtime inventory and root input
plan (the authenticated original runtime inventory has 900 names). Full old target/source maps are authenticated as records, not replayed
against remote live targets or all 7003 original source bodies locally. ELF
bodies are not required locally and are neither copied nor claimed rehashed.

Both F and RT must be clean; all source preimages and new-path absences are
checked before any write. Only the sixty authenticated formatted source bodies
are integrated, using the `apply_patch` CLI via subprocess without a shell.
The exact resulting bytes and changed path sets are checked before publication.
A partial integration failure is terminal for this helper: it does not revert,
retry or overwrite unrelated changes. Root must inspect any failed attempt.

Fresh output is F/qualification/projection-ordered-segment-cpu-v1. It contains
complete.json, all five small raw bodies per phase, source-overlay/{fe2o3,ferric}/..., both proposal
manifests/README/patch, controller/plan/test/primary observation and the two
publication scripts. Root writes the public README/progress only after success.
The result records original and retained paths, copy hashes, integrated source
pins, actual test totals, executable identities and explicit CPU-only limits.
Unformatted candidate/baseline bodies are checked in their retained proposal
trees but are not duplicated; no full source tree or target is published.
The seven large maps are all authenticated locally but are not copied into Git.
Their original and W-retained pins remain in result.json. A successful 75-phase
run therefore contributes 375 phase bodies, not all 382 raw bodies. This is only
copy selection; all map/source/old-target validation and postchecks remain.

The primary seventeen-policy-test record is a retained primary-agent observation,
not a remote ownership receipt. Runtime qualification does not establish GPU
queue ordering, arithmetic correctness, speedup, 2048/256 completion or production
authority. Host counter scope changed for ordered publish/wait; see the separate
counter-scope note before interpreting later native measurements.
