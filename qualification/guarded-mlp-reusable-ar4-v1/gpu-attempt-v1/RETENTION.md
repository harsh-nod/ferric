# Reusable AR4 Outcome Retention

These source-only templates adapt the reviewed shared-currentness GPU capsule
exporter and retainer. They authenticate an original reusable AR4 outcome as
data without executing a project module, model, compiler, test, native child or
GPU operation. No actual reusable GPU terminal or archive is bound yet.

## Bindings and Custody

The remote source is the fresh
`E/guarded-mlp-reusable-ar4-gpu-v228-v1` directory. Its nine selected root
bodies are the actual request, plan, preparation receipt, bound generator,
bound runner, reusable validator and three unchanged audit/ownership/announcement
helpers. The bound worker metadata is actual `24feb83a...` CPU and
`a5c5c8b3...` ELF. The parent receipt/product and five generated or bound root
pins remain `None` until observed. The terminal pin and terminal filename stay
`None` until the original attempt ends. The local retainer additionally leaves
the actual archive and bound exporter pins `None`.

The primary binds only observed values in separate copies. No failure is
rewritten as success. A recorded failure is retained with its exact raw prefix,
original errors, request count, spawn state and observed allocation values.
Complete native frame count and rechecked-success claims remain unset or false
for failures. A failed four-payload comparison is preserved inside the original
terminal even when no accepted observation/comparison files were written.

The archive destination is outside the immutable run root:
`E/guarded-mlp-reusable-ar4-gpu-evidence-v228-v1.tar.gz`. The canonical
destination is `qualification/guarded-mlp-reusable-ar4-v1/gpu-attempt-v1`.
Both destinations must be fresh; no previous failed or successful attempt is
overwritten. The retainer verifies everything before creating that destination.

## Verification

Both tools use the same pure data checks. Every declared original body joins
its size and SHA-256; all original phase result JSON bodies and command,
started, stdout and stderr pins join the terminal. Success requires the exact
eleven labels, natural zero exits, no cleanup signalling and recorded reaped,
absent process groups. The actual two-process parent/worker lineage and exact
guarded announcement join the copied native summary. All six idle snapshots
must record all eight GPUs idle and unchanged topology/boot state.

Success preserves the original validator's complete control/payload/transcript
result and native healthy Close. The profile and census functions are exact
source copies from the eight-test-qualified reusable validator. They independently
recompute the reusable profile and require the retained actual child-stderr
record's session, registration, device identities, Close and five samples:

```text
[715,711], [751,747], [787,783], [787,783], [787,783]
```

The census must also equal the checked observation and terminal allocation
counts. This recheck never substitutes predicted counts for recorded native
data. The exact census CPU `a1f048f2...`, historical announcement CPU and TF4
data-revalidation metadata must remain in the original readset.

The comparison function is copied from the reviewed reusable runner and run
only over retained bytes. All four current payloads and their actual input
histories must equal the selected ordinary run. Its recomputed result must equal
both the checked comparison file and original terminal. This is a required
regression check, not an independent full-model numerical oracle.

Retention does not import or rerun the original model validator. It rechecks
the recorded structure, custody, census and byte comparison described above.
Default full currentness is the explicit requested route; SharedFull and host
timing observation are false. Native/GPU execution belongs to the original
attempt, never these tools. Full-model numerical acceptance, long-workload,
throughput, performance and production-authority claims remain false.

## Bounds

The inherited caps are unchanged: 120 seconds, 256 MiB address space,
274 members, 8 MiB per body and 72 MiB aggregate/archive extent. These retention
caps are distinct from the unchanged native runner's 64 MiB case cap. Reads
check ordinary canonical files, stable identities and hashes before and after.
The exporter checks source closure before and after USTAR creation; the retainer
rejects duplicate, linked, special, traversal or PAX members and checks complete
manifest closure before writing anything.

Unknown bindings fail closed. No exporter, retainer or native invocation was
executed while authoring these templates. Actual outcome and retained evidence
will be independently checked by the primary after the one owned attempt.
