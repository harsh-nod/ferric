# Actual AR4 Retention Template

This data-only proposal retains the original outcome from the fresh
`guarded-mlp-model-gpu-v228-v3/ar4` attempt. The actual terminal filename and
byte/hash pin are intentionally unbound. Root must bind observed bytes only;
the template refuses before writing while those literals are pending.

The nine selected root bodies are the actual generated AR4 plan/request,
preparation controller/receipt, executed GPU controller, frozen ownership and
library helpers, qualified observation validator, and guarded-announcement
helper. External CPU receipts, ELFs, images, model inputs, parser qualification,
and prior TF4 data-revalidation bodies are not copied into this small capsule.
Their original pin metadata remains in the authenticated terminal/readset;
this is not a full transitive source or model-input archive.

All actual terminal raw files are retained byte-for-byte. A successful attempt
must contain exactly 77 raw files: 55 files from eleven owned leaves, seven
recorded topology snapshots, fourteen native files, and `observation.json`.
With its terminal this is 78 case files; nine root bodies plus the retainer,
this README, and the generated manifest produce 90 members with 89 manifest
pins. These are conditional success counts, not an observed outcome. Failed
prefixes use their exact authenticated raw map, preserve errors and the failed
outcome, and receive no successful-case interpretation.

The success checker joins all phase files and natural lifecycle metadata,
actual parent/worker ownership identities, guarded announcement, original
summary/payload hashes, four own-output autoregressive inputs, Close, recorded
idle/topology observations, and the controller's saved validator result.
It does not import or execute the validator, controller, worker, or model, and
does not independently establish Qwen numerical correctness. It never upgrades
the original TF4 outer failure or either failed data-revalidation attempt.

Ordinary canonical files, unchanged inode/link/size/time stamps, complete
pre/post hashes and closed source/destination rosters are required. The fetched
evidence consists of independent copied files, so this retainer requires link
count one; it does not read the external hardlinked Cargo ELFs. Bounds are
120 seconds, 256 MiB address space, 8 MiB per body, 72 MiB total, and 269 members.
The wider failure bound preserves the original controller's bounded raw prefix
instead of assuming every failure has successful stream sizes.

Only root executes this proposal after source review and actual pin binding:
`python3 -B retain.py`. The destination must be fresh. No GPU command, SSH,
project import, test, or retainer execution was performed by the author.
Independent full-model acceptance, sustained 2,048/256 workload acceptance,
performance claims, and production authority remain false.
