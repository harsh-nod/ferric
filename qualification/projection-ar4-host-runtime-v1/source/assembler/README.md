generated. Root must first run the separate reviewed runtime-audit selector
and author the actual compatibility reviews; their future pins are not
predicted here.

Run as UID9661 on MI350. The adapter sets CPU8/9, nice10, 2 GiB AS,
300 CPU seconds, 600-second checked wall bound, 4 MiB file cap and no core
dumps; existing tighter limits stay tighter. It starts no subprocess,
compiler, parent or worker. Frozen helpers do read current host/runtime
state and rehash the existing intake prerequisites.

It validates the complete frozen intake, supplied decisions and source
postchecks before exclusively creating four files: `request.json`,
`decode-review.json`, `plan.json`, `assembly.json`. Files are fsynced and
rehashed. Publication is not transactional across files; a failed write
can leave a partial fresh input directory, which is never reusable.
Temporary `layer_validation`, `prefix_contracts`, `observer_cpu`, `intake`
aliases are restored on success or failure.

Root can run the eight synthetic tests with ordinary `python3 -B
test_prepare.py` under bounded CPU-only settings. They cover lossless u64
request changes, freshness, mode and malformed review refusal, explicit
root decisions, alias restoration and retained config/notes bytes. They
do not import the real GPU package or run any real admission/audit.

Assembly is not new GPU evidence, numerical acceptance, full-model or
2048/256 qualification, timing/performance evidence, compiler-body replay,
or an independent runtime audit. It preserves the selected source, image
and producer/consumer boundaries of the frozen intake.
