# Shared-Full Host Evidence Retention

These source-only data tools export and retain an actual outcome from the fresh
explicit shared-full-currentness host-observer GPU controller. They never start a compiler, parent, worker, GPU
or project module. The original native terminal and raw bytes remain immutable.
Unknown terminal/name, CPU receipts/ELFs, bound controller/generator, generated
plan/request and preparation pins are `None`; the local retainer also requires actual archive and
exporter pins. No future outcome is inferred.

CPU receipts and Cargo products become metadata bindings only after actual
qualification. Neither ELF body is bundled. Root must fill only observed pins
into separate bound copies after their input/body joins. The explicit shared
GPU/checker template `2995cdc2` has a separate 15-test CPU gate (eleven host
cases and four topology cases); that gate is retained independently, not
bundled or requalified here. No prior conservative CPU or GPU success is
substituted for this generation. Root reported the current checker passed;
this source proposal does not claim to have executed it.

- Nine original controller/helper/generated root inputs.

The five selected earlier bodies are copied under `reference/ordinary-ar4/`.
Their contents and all embedded original paths are unchanged. The manifest
separately records their original FilePins. The reference terminal is the
actual ordinary AR4 `edf05cf2`; all four 606,976-byte bodies are authenticated
against that terminal and the current controller's readset.

## Checks

The exporter authenticates the closed current source tree, original terminal,
every raw/body pin, CPU/ELF admission metadata, generated input joins and
runtime limits. Successful receipts require the exact 11 phases, natural zero
exits, clean ownership retirement, strict parent/worker identities, original
guarded announcement, healthy Close, four genuine own-output AR frames,
all-eight-GPU idle samples and stable recorded topology. Failed receipts stay
failed and do not receive success or lifecycle assertions they did not earn.

The additional host-checker and comparison functions are source-identical to
the frozen GPU controller. They are rerun only as data parsers on retained
bytes. They close 587 snapshots / 586 intervals, strict u64 counters, the fresh
zero baseline, fixed group/epochs/device identities, explicit shared-full policy,
exact counter subtraction, actual wire completions and forward wall bounds.
The exact `FerricGuardedMlpSharedFullHostObservationV1` schema and all 587
`shared_full_currentness: true` snapshots are required. Cached admissions,
raw timestamps and operational-currentness counters remain excluded. The
checked host report must equal both the original terminal field and its saved
JSON; a conservative-schema report is not accepted by this generation. The ordinary full-model validator is not rerun by these tools.

The original four payload comparisons are independently recomputed against
the five retained reference bodies. Both equality and inequality are valid
diagnostic observations and are preserved exactly. Histories are compared per
position. Neither equality nor differences establish numerical acceptance or
causality. No reference framework or GPU computation occurs during retention.

The shared terminal's requested/verified flags are preserved. Timing comparison
and speedup claims remain explicitly false; this pair does not compare timings
to the old conservative host report. The five ordinary-AR4 reference bodies
and their pins are unchanged from the previous retention generation.

Host counters are inclusive and may be nested. Their durations are not device
time, GPU overlap or throughput. Generic paired-dispatch timing is incomplete.
Healthy Close does not convert those counters into performance authority.
All numerical/full-model acceptance, performance and production-authority
claims remain false. This is still a four-position diagnostic, not 2,048/256.

## Resource and File Safety

Both tools keep the preceding 120-second wall/CPU deadline, 256 MiB address-space
bound, 8 MiB individual-body bound and 72 MiB total/archive limit. The member
ceiling is 274, exactly five above the capture tool to allow the five selected
reference bodies; native controller limits are unchanged. Readers require
canonical regular single-link files, stable identities and exact hashes.
The exporter writes a fresh ordinary USTAR/gzip archive outside the immutable
case directory and rehashes all current/reference/tool inputs after writing.
The retainer verifies the complete archive before fresh-destination writes,
preserves the original manifest bytes and rehashes every retained body.

Run only after actual binding:
`python3 -B export_evidence_bound_v1.py` on MI350 with this document adjacent;
then `python3 -B retain_evidence_bound_v1.py` locally. No tool in this proposal
was executed by its author.
