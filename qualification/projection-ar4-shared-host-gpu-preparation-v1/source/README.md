## Bounded Pair

`run.py PLAN_PATH PLAN_SHA` executes one explicitly selected arm.
`pair.py PAIR_PLAN_PATH PAIR_PLAN_SHA` first authenticates both arm contexts,
then runs default followed by shared exactly once each. It refuses mixed
CPU generations, workers, model/prompt/seed/devices/images, deadlines or
provenance. Sessions, output directories, parent binaries and parent reviews
must be distinct. Both arm engineering reviews explicitly authorize only
their own one-attempt case; the pair does not synthesize approvals.

Every arm retains the original 4,300-second case / 4,000-second native leaf,
64 MiB evidence cap, 32 GiB native address-space cap, two CPU affinity cores,
nice10 children, pidfd/process-group cleanup, three exact-empty MI350 audits
before and after, unchanged platform checks, and no retry.
The pair is capped at 8,720 seconds, with two separate 64 MiB arm trees and
a bounded summary tree. Failure of an arm stops the pair; no substitute arm
or rerun is attempted. The old frozen supervisor is not modified.

The structural decoder remains byte-identical `0eb96d4a...`: four own-output
forwards, four payloads / 152 tensor slices and 576 control states per arm.
Before counter attribution, actual input histories must match at all four
positions. History divergence retains both arms but refuses a successful
paired attribution.

For every checked interval the numerator is only:

```text
sum(rank.full_currentness_ns) + group_full_ns + publication_full_ns
```

Command/read/write/dispatch and other inclusive counters are not added.
Configuration duration is not folded into that numerator. Forward wall time,
following-interval serialization time, Close wall time and interval wall
time remain separately labeled host diagnostics. Components are not claimed
to be disjoint latency; no GPU-time conversion or speedup acceptance exists.

Four payload byte comparisons report same-generation repeatability only.
They are not independent mathematical or framework accuracy. The fixed
default-first order, warmed caches, single pair, host scheduling and nested
scopes prevent a general performance conclusion. No 2048/256 workload,
production authority, numerical acceptance or full-model correctness is
established.
