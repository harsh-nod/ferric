# Resident-State Four Controller

After actual qualification and root review, the invocation remains:

```sh
taskset -c 8,9 /usr/bin/python3 -B run.py PLAN_PATH PLAN_SHA256
```

The parent command remains exactly the CPU633 executable followed by
`--request REQUEST --allow-unauthenticated-machine-code --observe-host-policy`.
The request selects CPU522 and the already qualified V7 image. One native
attempt, no retries, all 152 structural tensor rows, native Close/EOF and owned
process-group reaping are required. Three pre-audits and three post-audits run
with the unchanged topology/process checks; cleanup retains partial evidence
and refuses completion on any failure.

Unchanged limits: 4,000 seconds native, 30 seconds per audit, 4,300 seconds per
case; CPU affinity 8,9; child nice 10; native 32 GiB and audit 12 GiB address
space; 8 MiB streams; 64 MiB case evidence; 256 entries; 40/38 GiB disk floors.
The controller's UID, affinity, nice and pidfd ownership guards are unchanged.

New result schema: `ferric-p228-resident-state-decode-observation-v1`.
`worker_cpu_complete` and `worker_cpu_review` identify CPU522. New fields
`prior_deployment`, `prior_worker_cpu_complete`, and `prior_worker_cpu_review`
retain CPU475 lineage explicitly. Parent CPU633, V7 image, both runtime maps,
six standalone cases and six numerical prerequisites remain separately bound.

The unchanged structural helper never grants numerical or performance
acceptance. Independent reference diagnostics and same-image CPU475 bitwise
non-regression comparison occur only in a separate bounded CPU step after the
GPU controller terminates and its post-audits finish. No such result is
fabricated or implied by this draft.
