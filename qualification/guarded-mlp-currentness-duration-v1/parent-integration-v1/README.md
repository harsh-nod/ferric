# Parent Integration

Four actual tested parent files are integrated: the feature declaration,
shared codec registration, complete original-stderr parser, and parser tests.
The default and diagnostic MI350 qualifications used identical project
sources. Integration uses their final formatted source bodies.

| Qualification | Phases | Selected scopes | Passed | Library inventory |
| --- | ---: | ---: | ---: | ---: |
| [Feature disabled](../default-parent-cpu-v2/README.md) | 68 | 58 | 584 | 1047 |
| [Feature enabled](../diagnostic-parent-cpu-v2/README.md) | 69 | 59 | 595 | 1058 |

Both runs built seven executables and completed natural owned-process
retirement and all postchecks. The eleven added feature-enabled cases are
nine shared codec tests and two parent parser tests. No original named case
was removed. Library inventories are not full-suite execution claims.

The [complete integration postcheck](postcheck.json) authenticates all 1,299
canonical Ferric bodies and 827 runtime bodies. Both parent source maps
match the integrated Ferric generation. All 236 qualified worker bodies,
the parent lockfile and both workspace manifests/locks remain unchanged.
The prior [runtime/worker integration](../worker-integration-v1/README.md)
is retained as a separate checkpoint.

With the feature disabled, the original one-record policy protocol remains.
With it enabled, the selected Tail V4 parent authenticates both canonical
records and the entire original stderr file. It does not strip the diagnostic
record or substitute an ordinary-file hash.

Native admission and retention tools still need their own qualification
before the instrumented GPU run. No native result, independent numerical
acceptance, performance gain or Full2303 execution is claimed here.
