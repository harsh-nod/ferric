# AR4 Intake Contract

The closed plan schema is `ferric-p228-projection-ar4-decode-inputs-v1` and
the output label is `prefix-projection-ar4-decode-gpu-v228-vN`.
All non-label/schema fields are explicit path/bytes/SHA256 FilePins:

```
baseline parent_cpu worker_cpu parent worker request
projection_image lowering_complete inspection_complete decode_review
parent_runtime_review worker_runtime_review supervisor_tests
supervisor_test_sources layer_comparison mlp_image mlp_cpu
mlp_lowering_complete mlp_lowering_owner
```

The baseline is actual SiLU layer capture `67a23528`, not an invented AR4
receipt. Its frozen source and validator replay preserves the earlier layer,
TF4 and six-case provenance. The actual independent layer comparison is
`828f8fdb`; it establishes neither future AR4 token parity nor model acceptance.
The checked image receipts remain the previously retained genuine records.

The same new actual CPU completion must appear in `parent_cpu` and
`worker_cpu`. Before freezing, root binds its exact extent/SHA to `JOINT_CPU`
and the two actual Cargo ELFs to `BINARIES`. The intended label is
`projection-ar4-cpu-v228-v1`; a different actual attempt requires an explicit
reviewed namespace update, not a fallback or implicit retry. The new result
schema is `ferric-projection-ar4-cpu-result-v1` and its fixed source controller
is `p228-projection-ar4-cpu-v1/run.py`.

Admission joins the authenticated CPU1022 predecessor to the existing CPU988
layer prerequisite, checks source snapshots before/after, the exact AR4 source
manifest and additions/renames, and each selected artifact in the actual build
stdout. It does not rerun compilation, replay all transitive CPU dependencies
or treat a test count alone as evidence. The actual completion digest and
tested controller/source lineage are required.

The request remains the Rust `FerricFiniteProjectionResidualDecodeRequestV1`
wrapper with nested `decode`. Only nested mode `autoregressive` is admitted.
Source/model/device/prompt/Begin images, V7 prefix and dispatch bounds retain
the authenticated TF4 provenance; selected SiLU and projection images retain
their own checks. The worker ELF, session and output path are fresh. The wire
bootstrap supplies only seed 9112 and every later input is checked against the
previous observed argmax by `decode_validation.py`.

Both fresh runtime reviews bind the actual new ELF and inherited selected
platform. The root review schema is
`ferric-p228-projection-ar4-decode-engineering-review-v1`, with the same six
substantive review topics, explicit one-attempt gate and false authority flags.
No review is synthesized by these tools.

The separate pure receipt schema is
`ferric-p228-projection-ar4-decode-gpu-pure-v1`, with 52 named tests and exact
14-member source snapshots before and after. Root owns manifest generation;
the wrapper's existing bytes are bound in `TEST_RUNNER_SHA`.

CPU qualification, runtime review and structural AR4 success do not establish
independent numerical acceptance or performance. Genuine-framework AR4
comparison must use comparable histories and remains separately unperformed.
