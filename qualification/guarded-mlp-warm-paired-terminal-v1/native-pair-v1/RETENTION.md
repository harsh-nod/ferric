# Original Native Pair Evidence

This data-only helper retains original control/candidate evidence. It never
starts a child, calls the model, touches GPU APIs, reruns tests or imports a
native controller. It loads only the exact pinned pure observation validator
and announcement parser from the selected original source bodies. Successful
case validation repeats their data checks, not GPU execution or independent
model arithmetic.

The eleven shared root bodies are the six deployed source files, both actual
plans, both actual requests and preparation receipt. The exact actual worker,
parent and checker receipts/products are linked by their pins; their complete
CPU capsules remain separately retained. No executable, weight shard or model
bulk is copied. Five original ordinary-AR4 reference bodies are retained for
offline byte/history comparisons. That implementation parity is not an
independent numerical reference.

Each successful case must retain exactly 78 raw files plus its original
terminal: all eleven owned leaf results and streams, seven recorded topology
snapshots, fourteen native parent files and two checked records. Validation
requires the exact same qualified ELF pair and controller, distinct sessions,
six all-eight-device idle observations, actual two-process ancestry, four
original controls/payloads, own-output history, profile/transcript/Close,
the allocation-census checks provided by the qualified validator,
and byte equality to all four ordinary AR4 payloads. The candidate also must
match all four fully revalidated control payloads and histories. Its dispatch
counts are exactly `[0,0,36,36]`; control counts are `[0,0,0,0]`. Both retain
DefaultFull currentness and ordinary hidden reads.

A complete pair has **177 original archive members**: 158 case files, eleven
root files, five reference files, this document, the retention helper and an
export manifest. The manifest pins the other 176 bodies. Local `retention.json`
is additional. Exact 4-by-36 `segment_host_ns` observations are preserved as
host coordinator intervals; no timing comparison, GPU duration, speedup or
throughput claim is produced.

Terminal names and hashes are supplied only after observation. `failed.json`
is never promoted to success. `absent -` explicitly retains a spent directory
whose terminal is missing; it reports no verified observation. Failure
prefixes are closed by their original directory roster and hashes, without
inventing missing records. Candidate retention requires a fully revalidated
successful control. Control-only retention is allowed only before a candidate
directory exists. Empty or partial evidence cannot produce pair success.

The original per-case cap stays 256 files and 64 MiB. The combined archive has
a 531-member, 144 MiB compressed/expanded bound and 8 MiB per-body limit.
The helper is bounded to 180 wall seconds, 120 CPU seconds, 768 MiB memory,
fresh exclusive outputs and stable ordinary-file reads. All selected original
bodies and case rosters are rechecked after export; archive and extracted
bodies are rechecked during local retention. External model/ELF bodies are
not rehashed by this helper and no such claim is made.

Primary-owned remote export examples:

```text
python3 -I -B evidence.py export control complete.json CONTROL_SHA
python3 -I -B evidence.py export control failed.json CONTROL_SHA
python3 -I -B evidence.py export control absent -
python3 -I -B evidence.py export pair complete.json CONTROL_SHA complete.json CANDIDATE_SHA
python3 -I -B evidence.py export pair complete.json CONTROL_SHA failed.json CANDIDATE_SHA
python3 -I -B evidence.py export pair complete.json CONTROL_SHA absent -
```

Local retention adds the actual archive SHA before the same outcome arguments:

```text
python3 -I -B evidence.py retain ARCHIVE_SHA pair complete.json CONTROL_SHA complete.json CANDIDATE_SHA
```

Archives use `guarded-mlp-warm-paired-terminal-native-{control,pair}-evidence-v228-v1.tar.gz`.
Canonical destinations are the corresponding `native-control-v1` or
`native-pair-v1` under `qualification/guarded-mlp-warm-paired-terminal-v1`.
Existing destinations and archives are never overwritten. Retain failed
attempts in their original scope; do not repeat a spent native case.

The pure interface is `verify(bodies, outcomes)`. `bodies` excludes the export
manifest but includes the two retention source/document bodies. `outcomes`
maps each selected case to its original `name` and observed `sha256` (or
`None` for `absent`). Returned `cases[case].observation` is freshly revalidated
only for a successful case; `terminal` is its compact original pin. Every
return retains false numerical, full-model, production and performance
authority. This source handoff itself has performed no native run.
